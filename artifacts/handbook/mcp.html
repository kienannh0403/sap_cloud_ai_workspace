Cookie — hai đường đọc, hai cookie khác nhau

Đây là chỗ gây mất thời gian nhiều nhất.

  • MCP sap_cloud_dev giữ cookie riêng, đọc một lần lúc vsp startup. Refresh file cookie không làm MCP tỉnh lại — phải /mcp reconnect sap_cloud_dev trong terminal thật, hoặc restart Claude Code.
  • curl + ADT REST dùng tools/vsp/cookies.txt. Đây là đường duy nhất đọc được những loại object MCP không hỗ trợ.
  • Hai cái này trôi lệch nhau. Đã gặp cả hai chiều: MCP còn sống mà curl đã hết hạn (2026-08-13), và curl vừa refresh mà MCP vẫn dùng cookie cũ (2026-07-30).

Dấu hiệu hết hạn: request trả HTTP 200 nhưng body là trang HTML SAML login. Kiểm nhanh:

head -c 20 <file> | grep "<html"

Refresh bằng vsp --browser-auth, phải chỉ --browser-exec sang Chrome, và không pipe qua head — SIGPIPE giết vsp giữa lúc poll.

Đọc object

SAP(action=..., target="TYPE NAME", params={...})

Loại hỗ trợ — danh sách do chính tool trả về khi gọi sai

CLAS · PROG · INTF · FUNC · FUGR · INCL · DDLS · BDEF · SRVD
TABL · TABL_CONTENTS · DEVC · MSAG · TRAN · TYPE_INFO · STRUCT · CDS_DEPS

TYPE_INFO từng trả HTTP 406; đọc data element phải curl với Accept: application/vnd.sap.adt.dataelements.v2+xml.

Class lớn — đừng kéo cả file

SAP(action="read", target="CLAS ZBP_R_ZMFGKH01",
    params={"include": "implementations"})

SAP(action="read", target="CLAS CL_HTTP_DESTINATION_PROVIDER",
    params={"method": "CREATE_BY_COMM_ARRANGEMENT"})

include nhận implementations, definitions, macros, testclasses. Class standard thường ra 50KB+ nếu đọc cả. Sửa class lớn thì dùng CLONE + EDITSOURCE, không gửi lại full source.

Class rất lớn sẽ overflow và spill ra file — dùng luôn cái đó

read CLAS ZCL_FA_ENITY_ZGL02_3 (255 KB / 5.297 dòng) trả lỗi “exceeds maximum allowed tokens” kèm đường dẫn .claude/projects/<proj>/<session>/tool-results/mcp-sap_cloud_dev-SAP-<ts>.txt. Đừng đọc lại tràn context — phân tích bằng awk/grep/sed trên chính file đó: đếm construct, dò SELECT-trong-LOOP, ghép cặp SORT ↔ BINARY SEARCH. Nhanh hơn và không tốn context.

  • File chứa source + dependency context. Với ZGL02, class thật là dòng 151–4580; từ 4580 trở đi là định nghĩa class/interface khác. Phải chặn NR>=151 && NR<=4580 trong awk, không thì trích lẫn.
  • Statement ABAP trải nhiều dòng: READ TABLE x INTO y ở dòng này, BINARY SEARCH ở dòng khác. Grep một dòng sẽ ra rỗng — phải nhớ READ TABLE gần nhất phía trên rồi mới in khi gặp BINARY SEARCH.

Tìm object

search với target="Z*ZMFGKH01*" hoặc "I_PRODUCTPLANT*". Trả cả object SAP standard kèm PackageName — tiện để biết một view thuộc VDM nào. Trả null nghĩa là không có object nào khớp.

Action có trong danh sách nhưng không chạy

action="grep" được tool liệt kê trong “Valid actions” nhưng gọi thì trả No handler found. Muốn grep source thì kéo source về rồi grep tại chỗ.

Tạo / sửa DDIC table — chuỗi bắt buộc

  1. create với params.fields là JSON array — truyền source bị từ chối
  2. edit target="TABL …" không có handler → phải LOCK → UPDATE_SOURCE → ACTIVATE
  3. ACTIVATE nhả lock → tái dùng lock handle sẽ ra HTTP 423
  4. CLONE không hỗ trợ TABL
  5. Tham chiếu đơn vị trong define table phải đủ tên bảng: 'ztb_x.unit'

Bốn cái bẫy đã calibrate

Cả bốn cùng một dạng: tool báo thành công nhưng thực tế không phải.

bẫy 1

ACTIVATE trả success:true khi object vẫn inactive

  • Bằng chứng duy nhất về trạng thái: analyze + inactive_objects — object vừa đụng không được có trong danh sách.
  • Muốn biết lý do thì syntax_check, bắt buộc kèm content.
  • Ca thật: table ZTB_ZMFGKH01_A báo activate thành công nhưng vẫn inactive — nguyên nhân là annotation unit thiếu tên bảng.

bẫy 2

syntax_check chỉ báo error, không báo warning

InputKết quả
ABAP sai cú pháp (THIS IS NOT ABAP AT ALL ###)4 finding, tất cả severity: "E" → tool có báo
Warning chắc chắn có: gán 'ABCDEFGHIJ' vào c LENGTH 3null → warning không được trả về

Kết quả null chỉ chứng minh không có error. Không được nói “sạch”. Ca thật: warning Non-canonical structure of element nam… xuất hiện trong đoạn code tool này đã “pass”.

Mẹo: object_url chỉ cần là một object cùng loại đang tồn tại — check nội dung class console vào URL của một class Z bất kỳ vẫn chạy và không thay đổi gì trên hệ thống. Nhớ đặt tên class trong content khớp URL.

bẫy 3

action="query" trả 0 dòng một cách im lặng

User CB9980000022 không có quyền đọc business data (S_ABPLNGVS). Mọi view, kể cả I_CompanyCode, trả "Rows": [].

Kết quả rỗng không bao giờ là bằng chứng. Đã chặn việc chốt câu hỏi Q3 của ZPM01_EX và mọi test end-to-end phụ thuộc dữ liệu.

Đọc master data trong code ABAP thì khác: dùng WITH PRIVILEGED ACCESS để không phụ thuộc quyền người dùng cuối. Tiền lệ đang active: ZBP_R_TBUPLOAD_ZMA01.

bẫy 4 · 2026-08-19

syntax_check có lúc im hoàn toàn, kể cả với error thật

Bẫy 2 nói null = “không có error”. Nhưng có session syntax_check trả null cho mọi thứ. Cách phát hiện: chạy một control cố tình sai trước khi tin kết quả nào.

ControlKỳ vọngThực tế
Ghi vào field bịa <lfs>-Batch_ZZZ_CONTROL, host lên class có thật ZCL_ZMFGKH01_CREATE_PO 1 finding severity: "E" null

Component không tồn tại là hard error, không phải warning — nên đây không phải bẫy 2. Nghĩa là khi null xuất hiện, nó có hai cách đọc: “không có error” hoặc “check không chạy”. Không có control thì không phân biệt được, và cả hai đều trông như pass.

Hệ quả: không dùng syntax_check làm bằng chứng khi chưa có control. Đường lùi là đọc metadata thật — read BDEF … / read DDLS … cho biết field có tồn tại, có readonly, key gồm mấy field. Ca ZMFGKH01 ngày 08-19 chốt được toàn bộ theo cách đó.
